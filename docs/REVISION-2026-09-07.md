# Révision v0.2.0 — usage d’abord et recherche ouverte

## Réponse à la vérification demandée

La v0.1 demandait de comprendre le produit, mais ne conditionnait pas un profil
prêt à une recherche externe réellement exécutée. Elle ne représentait pas les
parcours d’usage et ramenait trop les résultats à un composant de code.

Constats vérifiés dans l’archive initiale :
- `tech_watch/profile.py` : aucune propriété `usage` ou `discovery` requise ;
  canaux limités à exactement sept familles.
- `skills/generate-tech-watch/SKILL.md`, étapes 2–3 : lecture du repo et choix
  de sources, sans phase obligatoire de recherche externe avant génération.
- `templates/watch/INSTRUCTIONS.md` : comparaison de chaque idée au code/tests ;
  rejet formulé d’un résumé général IA, sans distinguer un service de veille IA.
- `templates/watch/T0.md` : conclusions reliées à des composants existants.

## Modifications réalisées

Le skill commence par les usages. Une recherche de cadrage approfondie et
ouverte est imposée avant un profil prêt. T0 et chaque UPDATE exigent ensuite
leur propre exploration, même lorsque le code n’a pas changé.

`usage.py` valide publics, parcours, objectifs et questions liées aux usages,
avec finalité `product_improvement`, `domain_intelligence` ou `both`.
`discovery.py` valide les recherches exécutées et les sources lues déclarées,
l’élargissement, la contre-recherche, les limites, les dates et la couverture.
Les canaux peuvent être étendus ; la liste initiale n’est pas une frontière.

`state.py` exige un journal de recherche hashé propre au run pour geler T0 ou
accepter UPDATE. Une source vieille mais découverte maintenant reste admise.
Les instructions distinguent synthèse de domaine, décision et modification de
code. Aucune information n’a besoin d’un patch pour devenir pertinente.

## Vérifications et limites

Les tests et leur résultat exact figurent dans le rapport JSON externe livré.
Les scénarios de recherche des tests sont synthétiques, explicitement marqués.
La validation structurelle ne prouve pas la vérité ni la profondeur des recherches.
La recherche réelle est la responsabilité de l’agent hôte utilisant Internet.
Le Python n’est pas un navigateur/LLM autonome.

Cette correction n’a pas effectué les recherches spécifiques sur les dix repos,
ni observé leurs utilisateurs, ni publié sur GitHub, ni activé de scheduler.
Les références méthodologiques publiques consultées sont dans docs/RESEARCH.md.
Aucune baseline existante n’a été réécrite.
