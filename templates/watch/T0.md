# T0 — état initial de connaissance

## Deux objets à établir

1. Les usages : destinataires, objectifs, parcours, résultats attendus, limites
   d’observation ; puis acquis, décisions et fonctionnement vérifié à SHA fixe.
2. Le paysage externe pertinent : approches, articles anciens et récents,
   implémentations, alternatives et pratiques utiles à ses questions.

Le README seul n'est pas un T0. Il n'existe pas de date minimale des sources.
Le T0 est une recherche historique contextualisée, pas uniquement la semaine écoulée.

## Démarrer

Fixer `cutoff_at` avec fuseau, SHA du repo, questions, canaux obligatoires,
budget autorisé et run ID. Consigner la couverture prévue avant les recherches.
La date de génération du profil n'est PAS automatiquement la date du T0.
État : `T0_RUNNING` après écriture relue du journal de démarrage.

## Collecter, analyser, décider

Appliquer RECHERCHE.md : recherche initiale, expansion ouverte et contre-recherche.
La recherche de cadrage de la génération est une entrée, pas un T0 déjà fait.
Pour chaque source : identité, version, date de publication, date de découverte,
parties lues, éléments probants, limites et licence si un emprunt est envisagé.
Relier les conclusions aux usages et questions ; une information métier peut
être utile sans concerner un composant ni nécessiter de modifier le logiciel.
Distinguer faits vérifiés, documentation de l'éditeur et hypothèses à tester.
Classer : déjà présent, utile à tester, incompatible, insuffisamment prouvé,
refus motivé ou hors périmètre. Ne pas transformer chaque article en issue.

## Couverture et reprise

Un run trop long se découpe ; conserver un curseur et les artefacts déjà faits.
Ne pas annoncer « toute la littérature couverte ». Terminer la couverture
DÉCLARÉE avec ses limites, sans masquer une source requise inaccessible.
L'indisponibilité d'une source secondaire peut être documentée comme limite ;
elle ne peut pas être silencieusement assimilée à une lecture réussie.

## Geler une seule fois

Après couverture, analyse, déduplication, livraison et relecture : produire le
reçu décrit par `RECEIPTS.md`. Les artefacts
sont sous `runs/`. Utiliser `freeze-t0` lorsque le CLI est disponible ; sinon
réaliser exactement le même contrat et ne pas prétendre avoir exécuté le CLI.
Le gel produit `baseline/manifest.json`, les copies des artefacts et leur
SHA-256 ; l'état devient `UPDATE_READY`. Rien n'est gelé si le run est incomplet.
Les futures corrections sont dans UPDATE, jamais dans cette baseline.
